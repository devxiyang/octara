# Text input research: multi-line, password, platform text protocols

Scope: what Octara's single-line `text_input()` needs to become a multi-line text area and a secure field, and how far winit's IME falls short.

Sources: Octara (`crates/octara/src/kernel/edit.rs`, `app/edit.rs`, `kernel/text.rs`, `kernel/a11y.rs`, `docs/design/input.md`); Parley 0.12.0 and winit 0.30.13 and accesskit 0.25.2 in `~/.cargo/registry/src/*/`; clones under `~/code/archive/reference/` (`zed`, `rune`, `exact`). Items marked "known" are general knowledge, not checked against source.

## Octara today

- `kernel/edit.rs:60-120`: `Line` holds `shown` (value with preedit spliced at the caret), `stops: Vec<(byte, x)>` for ONE line, `scroll` (x only). `line()` re-measures with `Wrap::None` and recomputes scroll each call (paint, hit test, caret).
- `kernel/text.rs:106` `caret_stops` only reads `lines().next()` of the first paragraph after `break_all_lines(None)`. No y, no line index, no wrap. The paragraph cache is keyed `(node, slot)` per `\n` paragraph and per width (`text.rs:7-8`, `:203-213`), so wrapping and incremental reshape already exist for static text.
- `app/edit.rs:197-290`: commands are pure string ops on `(value, anchor, caret)` (`prev_grapheme`, `prev_word`, `0`, `v.len()`); no layout is consulted. `edit.move_to_start/end` are text-wide. Paste turns newlines into spaces (`:262`). Undo is whole-value snapshots (128 steps).
- `docs/design/input.md:116`: model is the runtime's own, not Parley `PlainEditor` (bypasses `TextEngine` and the paragraph cache). `:130`: "Single-line first; the multi-line text field comes later." `docs/TODO.md:148`: multi-line, password, deferring app rewrites during composition, caret inside composition are open. `ui-primitives.md:31`: multi-line, password, direct platform text protocols to do.
- Shell: winit `Ime::Preedit/Commit` plus `set_ime_cursor_area` from `caret()` (`octara-shell/src/lib.rs:296-300, :425`). `Kernel::caret` is one `line_height` tall at the line top (`edit.rs:140-146`): wrong once lines stack.
- A11y: `kernel/a11y.rs:176-177` sets the full `value` for every `Kind::TextInput`; `:267` copies it to the info that `inspect` serializes. Nothing masks it today.

## Parley 0.12 (verified in `parley-0.12.0/src/editing/`)

- `Layout::break_all_lines(Some(w))` wraps; `lines()`, `line_for_offset(y)`, per-line `metrics()` (block min/max coords) give rows. Octara already calls it in `text.rs:358`.
- `Cursor::from_point(layout, x, y)`, `from_byte_index(.., Affinity)`, `geometry(layout, width) -> BoundingBox` (caret rect with y), `next/previous_visual`, `*_visual_word`, `*_logical_word`.
- `Selection` carries `h_pos: Option<f32>` (the goal x). `move_lines(layout, delta, extend)` (`selection.rs:257`) reuses `h_pos`, picks the target line from the caret's rendered y, and falls to line start/end past the first/last line. `line_start` / `line_end` (`:317`, `:370`) are visual-line edges. `geometry()` / `geometry_with` (`:491`, `:503`) return one `BoundingBox` per line fragment: the selection rectangles.
- `PlainEditor` (`editor.rs`) has `move_up/down`, `move_to_line_start/end` (visual) and `move_to_hard_line_start/end` (logical), and an IME `compose: Option<Range>`. Its move/geometry code is on `Selection`/`Cursor`, which can be used over any `Layout` without adopting `PlainEditor`.
- Consequence: the "own model, no PlainEditor" decision (`input.md:116`) still holds; use `Selection`/`Cursor` against the cached paragraph layouts, not the editor.
- Gaps: a layout is per paragraph in Octara's cache, while Parley's `move_lines` and `geometry` expect one `Layout` for the whole text. A long text needs a paragraph-aware wrapper that maps (paragraph index, y offset).

## Zed / GPUI (`zed/crates/gpui`, `zed/crates/editor`)

- Editor: `DisplayMap` stacks inlay/fold/tab/wrap/block maps; soft wrap is a separate `WrapMap` over `SumTree`s, so rows are `DisplayRow`, and offsets convert in O(log n) (UTF-8, UTF-16, point). Heavy; Octara's texts are small, paragraph caching is enough.
- Vertical movement: `editor/src/movement.rs:119` `up_by_rows` takes `SelectionGoal` (`HorizontalPosition(x)`, `WrappedHorizontalPosition`, `HorizontalRange`), reads the goal x, else computes `x_for_display_point`, then `display_column_for_x(row, goal_x)`. Any horizontal move or edit resets the goal. At the first row it goes to column 0 (or stays, `preserve_column_at_start`). `line_beginning` (`:197`) and `indented_line_beginning` are display-row based (Home toggles indent).
- Password: `Editor::set_masked` / `DisplayMap.masked` (`editor.rs:9074`, `display_map.rs:241`) swaps text for a mask at display level; there is no GPUI-level password flag, no IME or secure-input hook (grep of `gpui*/src` for secure/password only finds credential storage). So GPUI leaves password semantics to the app.
- Text input protocol: `gpui/src/input.rs` `EntityInputHandler`: `text_for_range`, `selected_text_range`, `marked_text_range`, `unmark_text`, `replace_text_in_range`, `replace_and_mark_text_in_range(range, text, new_selected_range)`, `bounds_for_range`, `selection_bounds_for_range` (batch of line fragments, needed by UIKit), `character_index_for_point`, `set_selected_text_range`; ranges are UTF-16. Notifications: `notify_text_input_changed` / `notify_text_selection_changed`; `request_virtual_keyboard`.
- `TextInputConfiguration` (`platform.rs:2573`): `autocorrect`, `autocapitalize`, `suggestions`, `input_action` (Enter/Done/Go/Next/Search/Send, mirrors HTML `enterkeyhint`, Android `IME_ACTION_*`, iOS `UIReturnKeyType`). No password, no keyboard kind, no autofill hint.
- macOS: `gpui_macos/src/window.rs:3491` `first_rect_for_character_range` -> `bounds_for_range`, i.e. the candidate window follows the composition range, not just the caret line.
- Example `gpui/examples/input.rs` is single-line (one shaped line, `character_index_for_point`).

## Rune (`rune/crates/rune/src/edit*`, `rune-kit/src/text_input.rs`, `research/27-long-note-editing.md`)

- One `TextEdit` model for both; `text_input` is the single-line kit element, `text_area` has `.rows(n)`, `.auto_grow(min_rows, max_rows)` (height springs; scrolls inside after max, caret kept in view), `.height`, `.secure()`, `.revealed(bool)`, `.multiline()` on `text_input`. Naming to follow: `secure`, `revealed`, `auto_grow`.
- Caret motion (`edit/input.rs:205-245`): Left/Right use `visual_step` over the Parley layout; Up/Down call `text::move_line(layout, display_index, down)`, no remembered goal x there (grep: no goal in `edit/`); at the first/last line they jump to text start/end. Home/End: text ends on macOS, visual line edge elsewhere (Ctrl: text ends). PageUp/Down are no-ops (`input.rs:157`).
- Submit: in a multi-line field plain Return submits via `on_submit`; Shift+Return / Option+Return insert a newline (`research/27:135`); secure text areas use Cmd/Ctrl+Return to submit and Enter inserts a newline (`text_input.rs:390-393`).
- Secure (`edit/secure.rs`): `Masking::{Plain, Shown, Hidden{multiline}}`. Hidden single-line: one bullet per Unicode scalar (`"•".repeat(chars)`, not per grapheme, chosen so caret math stays aligned). Hidden multiline: a fixed 12-bullet mask that hides length and line count; clicks and unshifted nav go to the end, shifted nav selects all, edits only append/replace-all/backspace at end; "reveal to edit an interior position".
- Secure protections: no undo (history cleared and unrecorded), no copy/cut (`text_input.rs:347` hides copy button), IME composition cancelled, marks/blocks cleared, buffers zeroized on drop (`zeroize`), `Ime` payloads zeroize on drop, `Debug` prints `[redacted]` (`edit.rs:72`), no accessibility text while hidden, `revealed` keeps all protections except display.
- IME: `Ime::{Preedit(String, Option<(usize, usize)>), Commit, Enabled, Disabled}` (`edit/ime.rs`): same shape as winit; preedit has a cursor range.
- Perf (`research/27-long-note-editing.md`): one multi-line field reshapes the whole text per keystroke: 2.2 ms at 5 KB, 12 ms at 50 KB, 46 ms at 200 KB (M4 Pro); caret motion and scroll stay under 0.5 ms. Advice: one field per block beyond ~10 KB. Lesson: per-paragraph incremental reshape, which Octara's cache already has, is the fix Rune did not make.

## Exact (`exact/` Contract DSL, `docs/reference.md`, `QUEUE.md`)

- Uses native widgets per host (a `textarea` node, AppKit `TextAreaScroll` in `Mac/NativeFieldsMac.swift`, `markup="markdown"`), so wrapping, goal x, IME and secure entry are the platform's. Little to copy for a self-drawn field.
- Relevant carried rules: IME composition owns Enter/Escape (already adopted, `input.md:100`); app rewrites of the value are deferred during composition (`input.md:114`, TODO open); Windows IME qualification checks Japanese conversion, candidate placement at 150% scale, dotted/solid clause underlines (`QUEUE.md:247`). Did not find a secure-field or autofill spec (not verified beyond grep).

## winit 0.30 and the platform protocols

- winit (verified `window.rs`, `event.rs`): `Ime::{Enabled, Preedit(String, Option<(usize,usize)>), Commit, Disabled}`; `set_ime_allowed`, `set_ime_cursor_area(pos, size)`, `set_ime_purpose(Normal|Password|Terminal)` which is Wayland/X11-only ("unsupported" on macOS/Windows/iOS/Android/Web). No surrounding text, no marked range query, no selection sync, no reconversion, no per-range rects, no `character_index_for_point`, no content type (email/number/OTP/autofill), no enter-key hint, no secure input.
- What a framework needs (known): macOS `NSTextInputClient` (`attributedSubstringForProposedRange`, `selectedRange`, `markedRange`, `firstRectForCharacterRange`, `characterIndexForPoint`; UTF-16): dictation, Writing Tools, emoji picker, reconversion, press-and-hold accents. iOS `UITextInput` (positions/ranges, `selectionRects`, autocorrect, Scribble, floating cursor, `isSecureTextEntry`, `textContentType`). Android `InputConnection` (`getTextBeforeCursor`, `setComposingRegion`, `getSelectedText`, `requestCursorUpdates` for candidate anchoring; `InputType` flags incl. `TYPE_TEXT_VARIATION_PASSWORD`, autofill hints). Windows TSF (`ITextStoreACP`: `GetText`, `GetSelection`, `GetTextExt`, composition attributes) vs `WM_IME_*` which loses reconversion. Linux `zwp_text_input_v3` / IBus: `set_surrounding_text`, `set_cursor_rectangle`, `set_content_type` (purpose/hint incl. password, sensitive_data), `commit_string`, `preedit_string` with cursor; the compositor needs surrounding text to do reconversion.
- GPUI and Rune implement the platform protocols directly (Rune's research `05-text-ime-a11y-layout.md:12`: NSTextInputClient, UITextInput, TSF, text-input-v3; `gpui_apple`/`gpui_ios`, `gpui_windows`, `gpui_linux`). Octara's `input.md:127-129` already defines the GPUI-shaped protocol in UTF-8 with UTF-16 conversion; the shell only wires preedit/commit.

## Elsewhere (known)

- AppKit `NSTextView`/TextKit 2, UIKit `UITextView`, Android `EditText`, Flutter `EditableText`, browser `<textarea>`: all keep a goal column across vertical moves (reset by any other motion/edit), Home/End per visual line (macOS: Cmd+Left/Right visual, Cmd+Up/Down text ends), PageUp/Down by viewport height with the caret keeping its goal x, Enter = newline, Shift+Enter or Cmd+Enter app-defined. `<textarea rows>` and `field-sizing: content` + `min/max-height` are the auto-grow model; Flutter `minLines/maxLines`; UIKit auto-grows via `sizeThatFits`.
- Password: AppKit `NSSecureTextField` (and `EnableSecureEventInput()` while focused to stop key logging by other processes and block most IMEs); UIKit `isSecureTextEntry` (disables autocorrect/prediction and briefly reveals the last typed character; copy behavior unverified); Android `TYPE_TEXT_VARIATION_PASSWORD` / `TYPE_TEXT_VARIATION_VISIBLE_PASSWORD`, last character shown for ~1.5 s (system setting); browsers `type=password` with `autocomplete=current-password | new-password | username | one-time-code`. Windows `ES_PASSWORD`, `ImmAssociateContext(NULL)`. All mask per grapheme/char and refuse copy/cut/drag; undo policies vary.
- AccessKit (verified `accesskit-0.25.2/src/lib.rs:113, :2117`): `Role::PasswordInput` and `Role::MultilineTextInput` exist; in a `PasswordInput`, `value` "must only contain masking characters"; a revealed password uses `Role::TextInput`. Multi-line text is exposed as `Role::TextRun` children per visual line with character positions (Rune research `05:269`).

## Conclusions

1. API: keep one constructor, add modifiers on `text_input()` (Rune naming; GPUI has none): `.multiline()` (newline on Enter, wraps), `.rows(min, max)` (height from line height, scrolls inside after max; Rune calls the second form `auto_grow`, Flutter `minLines/maxLines`; one method `rows(min, max)` is closer to Octara's terse style), `.secure()`, `.revealed(bool)`; later `.input_action(..)` (GPUI `TextInputAction`) and `.content_type(..)` (username, new-password, one-time-code, email, number). Model remains `value` + `on_input`. Needs semantic confirmation per the Native-not-web memory before shipping.
2. Enter: multi-line inserts "\n" on Enter and Shift+Enter; `on_submit` fires on Cmd/Ctrl+Enter (Rune's secure-area rule). A chat-composer variant (Enter submits, Shift/Option+Enter newline, Rune's default for multi-line) is a separate modifier, e.g. `.submit_on_enter()`. Single-line unchanged. Confirm which is the default before implementing.
3. Layout: extend `TextEngine` with a multi-line query beside `caret_stops`: `caret_rect(key, byte, affinity) -> Rect`, `byte_at(key, x, y)`, `line_range(key, byte) -> visual line (start, end)`, `selection_rects(key, range) -> Vec<Rect>`, `move_line(key, byte, goal_x, delta)`; implement with `Cursor`/`Selection` over cached paragraph layouts broken at the content width (`text.rs:358`), and in the monospace test engine with fixed-column wrapping. Re-use the paragraph cache; map global y to (paragraph, local y) using cached heights. Keep the "own model, not PlainEditor" decision (`input.md:116`).
4. Editing model: byte offsets stay; selection becomes `(anchor, caret, goal_x: Option<f32>)` stored with the runtime state. Up/Down/PageUp/PageDown use goal x (Parley `h_pos`, GPUI `SelectionGoal`); any other move, edit, click or `on_input` rewrite clears it. First/last line: go to text start/end (Rune/AppKit). Home/End: visual line edge (Windows/Linux), Cmd+Left/Right visual line, Cmd+Up/Down text ends (macOS); Ctrl+Home/End text ends; add `edit.move_to_line_start/end`, `edit.move_up/down`, `edit.move_page_up/down`, `select_*` twins; delete-to-line-start uses the visual line. Word and grapheme moves unchanged (cross lines naturally). Paste keeps newlines when multi-line.
5. Rendering: caret at `caret_rect`, selection as one quad per line fragment (`selection_rects`), preedit underline per fragment; clip to the content box. Replace `Line.stops` with a per-query API and drop the per-call `line()` recomputation (cache by `(value, width, preedit)` version).
6. Scrolling: a multi-line field with `.rows(min, max)` clamps its box height and owns a vertical scroll offset (like the current x `scroll`), kept as minimal as possible to show the caret rect; wheel goes to it first, at its edge not to the outer container (`input.md` Scrolling, Rune rule). Unbounded-height fields (no max) grow and let the enclosing scroll container move: report the caret rect to the scroller (`scroll_into_view`) on edits so typing stays visible. Auto-grow height is measured with the same paragraph cache (min-content/max-content queries are already cached by width).
7. Performance: Parley reshape is per paragraph (`\n`), width changes only re-break (`text.rs:7-8`); with a dirty-paragraph hint the keystroke cost is one paragraph, not the whole text (Rune's measured 12 ms at 50 KB shows the cost of not doing so). Undo snapshots copy the whole value: switch to range edits (`replace(range, text)` records) before long texts; cap memory.
8. IME: composition is spliced at the caret and may contain "\n" only if the engine says so (rare); preedit rect = the composition range's `selection_rects`, and `place_ime` should use the caret's own rect within the composition (preedit cursor `(usize, usize)` from winit, TODO "caret inside composition") with the real y (not the line top), using the scrolled position. Keep Enter/Escape owned by the IME and defer app rewrites during composition. Real fix for surrounding text/reconversion needs direct protocols (item 12).
9. Password semantics (adopt Rune's list): `.secure()` masks with U+2022 per grapheme (Rune uses per scalar to keep caret math simple; grapheme is more correct but then caret math must be done on the masked string, so draw masked text through the same engine and map offsets per grapheme); disables copy/cut (and drag), undo/redo history (clear on `secure`, no snapshots in `EditState`), word motion (one word), IME composition (`set_ime_allowed(false)` while focused; winit `ImePurpose::Password` on Wayland/X11), spell/auto-correct; reveal toggle `.revealed(bool)`. Multi-line secure is rare: support single-line only first (Rune's fixed-mask multi-line is the fallback).
10. Mobile: reveal-last-character for ~1.5 s after each typed character (platform default on Android/iOS) as a runtime timer on virtual time (testable with `advance`); desktop shows none. macOS shell calls `EnableSecureEventInput` while a secure field is focused and `DisableSecureEventInput` on blur/exit (known; verify refcount: calls must be balanced). iOS/Android set `isSecureTextEntry` / `TYPE_TEXT_VARIATION_PASSWORD` when native text protocols arrive; until then winit gives nothing on those.
11. Accessibility and agent output: a secure field maps to `Role::PasswordInput` with `value` = bullets only (accesskit contract); `Role::MultilineTextInput` for `.multiline()`, with `TextRun` children per visual line later. Today `kernel/a11y.rs:177` and `:267` copy the raw value into AccessKit and the inspector info: both must emit the mask (fixed length or none) for secure nodes, and `SetValue` actions on secure nodes are allowed but never echoed. `octara inspect` snapshots (`octara.inspect/1`: `value` column), screenshots-as-text, `Debug`/log output of `TextField`/`Snapshot`/`Node` input state (selection offsets leak length), and diagnostics messages must never contain the value, the selection range, the undo stack or the clipboard text; the headless `text_field()` test API should return the real value only behind an explicit, test-only call. Add a diagnostic code for "secure field value read through inspect" only if a read path remains. Redacted `Debug` (Rune: `[redacted]`) and zeroize on drop for value/preedit/edit payloads (`zeroize`) for the secure node; screenshot tests should still see the bullets.
12. Direct platform protocols: do after multi-line. First extend `Kernel` with the GPUI-shaped handler already in `input.md:127` (`text_for_range`, `selected_text_range`, `marked_text_range`, `replace_and_mark_text_in_range`, `bounds_for_range` returning rect lists, `character_index_for_point`, plus `selection_bounds_for_range`) in UTF-16; then per platform: NSTextInputClient (macOS) and UITextInput (iOS), TSF (Windows), InputConnection (Android), text-input-v3 (Wayland) bypassing winit. Add a `TextInputConfiguration`-like struct (`input_action`, `content_type`, `autocorrect`, `secure`) that the shell maps per platform, so `.secure()` and autofill hints reach `isSecureTextEntry`/`textContentType`/Android hints.
13. Tests (headless, no window): extend the monospace engine to wrap at a column width so tests are deterministic. Cases: soft-wrap Up/Down with goal x preserved across a short line and restored; Home/End on a wrapped line vs logical line (per platform `Chord` map); PageDown by viewport rows; selection rects across 3 lines (count and extents); Shift+Enter vs Enter; `rows(2, 5)` height growth and clamp, vertical scroll keeps caret in view and the enclosing scroll container receives a scroll_into_view; IME `set_composition` on line 2 places `caret()` on line 2 with correct y; paste of "a\nb" keeps the newline multi-line and becomes a space single-line; secure: inspect/a11y value is bullets only, copy/cut/undo no-op, no `Debug` leakage (assert the string never appears in snapshot JSON, logs, diagnostics), reveal toggles, last-char reveal timer with `advance`. Add one real-Parley test mirroring `parley_wraps_and_caches_by_paragraph` for wrapped caret rects.
