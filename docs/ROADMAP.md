# 实现边界与路线图

| 能力 | 仓库目前可以检查什么 | 仍需取得的证据 |
| --- | --- | --- |
| 状态与结构 | Signals、带 key 的集合、挂载和退休；同名对象跨重排、热重载和重建的测试 | 文件重命名中途重排的完整时序，包括原生编辑期间发生删除。[身份测试](../crates/octara/tests/integration/structural_identity.rs) |
| 桌面窗口与绘制 | winit 宿主、CPU 参考绘制、GPU 绘制、检查通道和截图。macOS 有原生编辑及视图适配 | 多窗口动作接收者、跨宿主的显示回执与原生像素；按平台记录输入途径。[宿主](../crates/octara-shell/src/) |
| 输入与语义 | 焦点、快捷键、语义操作、滚动、联动触摸位移分配、文本选择和输入法桥 | 移动系统触摸中断、桌面触控板阶段归属、外部值更新与原生文字组合的验收。[输入](design/input.md) |
| 组件组合 | 组件库使用公开视图接口实现按钮、表单、弹层、Tabs 和可搜索选择器 | 按桌面、触摸和辅助操作复核哪些行为需要下沉。[组件库](../crates/octara-kit/src/) |
| 移动端 | 无窗口宿主可测试紧凑布局与触摸目标 | iOS 或 Android 宿主、软键盘占用、手势中断和系统返回的真机或模拟器证据。桌面窄窗只验证布局 |
| Agent 验证 | 可检查语义树、校验目标代次、连接桌面窗口并用构建收据核对进程 | 将时序中的接管、取消、命令归属与实际系统反馈逐项核验。[观察指南](design/agent-knowledge.md) |

## 推进顺序

先用文件重命名和嵌套拖动写出具体状态转移及失败条件。接着对照已有实现，分别记录可复用的协议、缺失事实和真正需要的公共入口。确定状态归属后，再分别实现并做宿主验收。保留无窗口、窗口注入、真实系统输入三种证据的来源。[交互时序](design/interaction-scenarios.md) · [工作清单](TODO.md)
