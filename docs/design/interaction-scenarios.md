# 用交互时序推导原语

以下是设计样本和验收条件。它们独立于仓库里的演示应用，覆盖桌面鼠标、键盘、触摸和系统输入服务。每一行描述一个可以观测、也可以做错的转折点。

## 桌面文件管理器：重命名时发生重排

| 时刻 | 谁持有状态 | 应该观测到什么 |
| --- | --- | --- |
| 文件 A 和 B 被多选，键盘焦点移到 B | 应用持有选中的业务 key；窗口记录焦点 | 移动焦点可以不改变选中集合，读屏能分别报告两者 |
| 开始重命名 B，输入法送来组合文本 | 编辑会话持有草稿和选区；模型仍持有原文件名 | 用户看到下划线和光标，磁盘上尚未发生重命名 |
| 目录刷新把 B 挪到首行 | 列表按业务 key 移动仍挂载的行；窗口更新几何 | 即使旁边还有同名文件，焦点、草稿、选区和动作目标仍跟着 B |
| 用户按 Escape 或确认 | 编辑器结束组合，应用按明确的提交策略处理重命名 | 取消恢复原值；确认只产生一次业务操作。系统输入法消费的确认键不能再触发第二次提交 |
| 后台删除 B，随后出现同名的新文件 | 旧挂载与输入会话退休；新文件依业务身份获得新目标 | 对旧目标发出的延迟编辑和 Agent 操作都无法修改新文件 |

行被虚拟化卸载时必须单独决定策略。产品若要继续编辑，可以固定当前编辑行，或将草稿寄存在文档会话。内核负责明确报告卸载和目标失效；同名重建不能隐式恢复一个已结束的原生会话。

## 移动地图：面板与内层列表交接拖动

设面板距展开上限还差 12 个逻辑像素，内层列表可以继续向前滚动。本例的产品策略为先展开面板。

| 时刻 | 分配与提交 | 可验证结果 |
| --- | --- | --- |
| 手指落在列表按钮上 | 按钮可预览按下，等待手势归属 | 抬手之前业务动作尚未执行 |
| 拖动越过阈值 | 窗口撤销按钮的按压预览，把后续位移交给拖动 | 此次接触最终抬手时按钮触发次数为零 |
| 后续一帧位移 30 | 面板消费 12，列表获得剩余 18 | 同一方向两处实际消费之和为 30；没有跳变或重复滚动 |
| 手指反向，或系统中断 | 依据列表边界重新分配位移；中断结束本次会话 | 已显示的滚动位置保持一致，取消后没有点击或迟到的惯性启动 |

上推先展开、下拉先耗尽列表是产品策略。窗口只需要能表达每次输入的参与者、已消费量、剩余量和取消。这些量也可以在触控板上验证；设备坐标到逻辑坐标的变换须在日志中区分。

## 用另外三个场景找遗漏

| 场景 | 观察值 | 能排除的错误设计 |
| --- | --- | --- |
| 平板分屏中的中文表单，软键盘出现后窗口再缩窄 | 已提交值、组合区、选区、可视光标和候选窗位置 | 用设备型号决定布局，或每次重排重建编辑器 |
| 两个桌面文档各有撤销栈，从工具栏、菜单和快捷键执行撤销 | 当前窗口、实际动作接收者、撤销可用性和修改后的文档 | 把命令保存在进程级单例，或给三个入口复制三套判断 |
| 手机相册交互式返回，进度过半后取消，再次返回并完成 | 原页面、阅读位置、可操作目标和资源释放次数 | 只要开始返回就释放页面，或取消时重新挂载同名页面 |

先在确定性宿主断言状态与顺序，再用真实窗口或模拟器核对系统参与的环节。无窗口测试、窗口 Inspector 注入和系统输入分别记结果。待实现的移动宿主不能产生模拟器验收结果。[路线图](../ROADMAP.md) · [现有验证入口](../../examples/README.md)
