# 核心原语的四份契约

日期：2026-11-17。状态：**设计提案，未实施**。
接续[原语推演](core-primitives-derivation.md)。本文规定候选默认政策，不表示当前实现全部符合。
未新增代码、测试或运行证据；能力分组不机械转为公开类型，具体 Rust 签名待下一步推演。
后续修订：本文是问题与候选政策清单，不是全部待实现要求。
按 [W3C 原语审查](../research/w3c-core-primitives.md)，core 应公开足以独立构建 UI 的通用能力；
kit 的装配便利不能成为输入、编辑、语义与弹层机制的唯一入口。

## 1. 共同基础

保留 Rust + Signals、一次构建、保留式文档、scope 执行与释放政策。
App 负责资源与入口，窗口负责交互事实，文档负责内容与编辑过程，应用负责业务值。
kit 组合这些能力，不拥有第二套编辑器、焦点系统或执行器。

“稳定边界”指一轮响应式传播及相关结构更新完成、准备交互修复和输出的阶段，
不是全 App 原子快照，不承诺回滚任意 Rust 副作用。
执行用户代码前释放内部借用，返回后重新检查目标和执行所有者。
结构变化过程中保持内存和身份安全；完整性诊断等相关更新稳定后，避免误报挂载中间态。

## 2. 内容与结构契约

### 所有权与组合

| 事实 | 唯一修改所有者 | 对外含义 |
| --- | --- | --- |
| 应用布局 children 与顺序 | 结构协调器，接收 View 声明 | 普通组合、条件与 keyed 重复 |
| 文本 run、链接范围、内部语义对象 | 对应文本内容 | 更新文本不触碰应用 children |
| 编辑文档 | 挂载的输入内容 | 改外观或外围布局不重建编辑器 |
| 节点身份与释放状态 | 文档分配/移除机制 | 旧目标不因同名对象出现而复活 |
| key 对应的组件状态 | 所属结构区域 | 合法重排保持状态；不承诺跨任意父级迁移 |

容器接收应用布局 children；文本、输入、图标、图片、Canvas、原生视图不接收任意应用 children。
这是 Octara 选择的简化政策，不照搬 Exact 所有节点能力。Canvas 上的控件使用外部叠层；
富文本通过专用内容接口表达。私有表示是否使用内部节点不影响此契约。
结构接受能力、测量来源、语义后代分别定义，不能用一个 leaf 标记代替。

### 更新、身份与失败

- 属性更新保持对象身份；几何是否重算由具体属性失效决定。
- keyed 区域内重排保留项状态及编辑身份；重复 key 明确拒绝，不任选一项。
- 移除后用相同 key/name 创建是新一轮挂载，旧目标不得命中新对象。
- 内部链接也有身份规则：位置或 URL 相同不证明对象连续；明确增量更新可保留未删除对象，
  无法证明连续性的整体替换使旧内部目标失效。
- 禁止环、重复所有权及非法内容。构造层尽早拒绝，内部结构写入口仍检查。
  拒绝的结构操作不留下部分改写；不把这一保证扩大为整个 UI 更新的事务回滚。

View 是可消费的组合描述，挂载表示不公开。容器和内容共享样式能力，但不共享所有结构方法。
公开层比较少量具体 builder 与受限 El 两种选择，不为每种组合状态生成泛型。
show、keyed、each 等便利入口可以保留，底层挂载、移除和释放共用规则。

**验收反例：**文本更新删掉应用孩子；重排重建编辑器；旧链接点击替换后的新链接；
为了加图标不得不把文本当容器。

## 3. 语义与动作契约

### 三种责任

角色和名称描述对象是什么；动作能力规定能做什么；窗口路由决定本次输入能否到达。
role 不自动构成完整控件，鼠标回调也不自动提供键盘与 AX 行为。
kit 标准按钮一次装配完整行为，自定义控件复用基础能力，不要求应用重新实现交互规则。
低层动作能力需要服务自定义 UI，但公开类型是否继续叫 Behavior 尚未决定。

激活、切换、选择选项、调整数值分别有类型化载荷与合法性，不创建字符串命令总线。
不同输入路径共享对应动作的资格和规则，不意味着所有输入都变成 click。
OS 路径负责命中、手势、IME；Inspector 直接动作不能伪称验证了真实 OS 输入。

### 顺序与资格

1. 路由输入：输入法优先处理相关按键，再按窗口交互范围确定目标。
2. 执行边界验证目标、所有者、动作能力、禁用状态及载荷。
3. 执行组件内部行为和必要的值提议，不持有跨用户回调的内核借用。
4. 返回后重新验证资格，继续仍适用的行为与应用通知。
5. 传播接受值，修复交互并准备输出；回调返回不代表上屏或异步业务完成。

按下时可用、释放前禁用，不能激活。回调移除目标后，不继续操作新同名对象。
不能强行中断已经开始的同步 Rust 回调；重新检查约束下一步，不撤回已发生的副作用。
键盘消费控制尚未发生的后续路由；应用通知不具有事后撤销能力。

### 配置目标与内容

动作根拥有角色、名称、禁用与焦点资格，视觉标签是其内容。纯文本标签可同时提供默认名称；
自定义标签保留明确名称来源，不能随意拼接全部子树文字。
装饰内容不重复暴露，独立语义按控件规则保留。按钮标签中嵌套独立按钮或编辑器应拒绝；
多个动作使用兄弟控件表达，避免模糊激活目标。
Field 的名称、描述、disabled、value 和输入回调指向实际输入，不静默落到包装容器。
换外观/内容复用同一个动作根，不靠覆盖 role/handler 解决冲突。

disabled 阻止对应用户/AX/Agent 动作，不阻止应用更新模型；readonly 不自动禁止选择与复制。
loading 除非组件明确规定，否则不等于 disabled。Tab、程序聚焦和禁用后的焦点修复逐控件定义。

**验收反例：**换标签丢键盘操作；Agent 可操作禁用控件；标签关联包装容器；
组件回调移除自身后应用通知仍执行。

## 4. 编辑与业务值契约

### 文本绑定与业务适配

文本绑定表达可编辑文本；简单应用可用一个 String Signal 同时承担业务值。
NumberField 等还需要文本草稿，解析后的业务值可以是 Option、整数等普通 Rust 类型。
草稿具有独立含义，不是无条件镜像模型。空串、负号、超界是否能提交由上层政策决定。
文档拥有 selection、composition、历史和当前编辑文本；绑定提供同步接受文本的来源。
解析、可提交性与错误显示分别派生，不无条件 OR 成一个 invalid。

### 候选默认：隔离预编辑，明确接受与重置

继续采用 Octara 预编辑与已提交文本分开的方向，不照搬 Exact 每次 marked text 都发 input 的政策。
预编辑更新文档和原生查询，普通值回调不把候选串当作已接受值。
应用订阅预编辑仅在真实用例需要时另行论证。

| 情形 | 候选默认结果 |
| --- | --- |
| 普通编辑或无待处理覆盖的 IME 提交 | 提议完整文本，执行同步接受回调，读取最终绑定值并协调；不能依赖 Signal 是否发出变更通知 |
| 接受回调保留旧值 | 拒绝文本提议，恢复接受文本及编辑前选择；旧 Signal 未变化也必须处理 |
| 接受回调改写文本 | 使用最终接受文本，按明确选区映射和历史政策协调 |
| 同值外部回写，且无待应用值 | 与已提交文本相同则不改 selection、composition、历史 |
| 非预编辑期间不同值外部回写 | 替换编辑文本，不伪造用户输入通知 |
| 预编辑期间不同值外部回写 | 保存最后一次显式待应用值，不打断输入法；后续同值写入也能覆盖这个待应用值 |
| 预编辑结束且有待应用值 | 应用待处理值；不把已被替换的最终旧草稿再次提议给应用，避免覆盖重置 |
| 预编辑结束且无待应用值 | 提交走普通提议/接受；取消恢复本次 composition 开始前已提交文档 |
| 字段移除、窗口关闭或编辑目标代次失效 | 释放预编辑与待应用值，拒绝旧平台回调 |

“显式待应用值优先”是本提案的选择，与 Exact 的先通知最终编辑再处理仍待应用值不同，
必须经平台验证再定稿。仅实际绑定更新形成待应用值，布局读取旧接受值不算新重置。
同值强制重置不能靠 Signal 写相同内容隐式表达；如需此功能，另定编辑操作，不扩大所有 setter 语义。

普通接受保留编辑计算的光标与撤销记录；拒绝不加入成功撤销项。
规范化或外部替换保留可对应的未变区段选区位置；落入替换区的端点移至该区新末端，
并修正为合法文本边界。初版将改变文本的非原样接受/外部替换作为历史边界，清除不再可靠的撤销/重做。
不能让旧撤销恢复另一个业务文档；更复杂编辑器的历史需求后续通过领域操作表达，不先引入全局事务。

Enter 先交给 IME，同一次候选确认按键不再触发表单提交。blur 是否规范化数字归 kit 政策。
Save 读取当时稳定的草稿/业务状态并验证，不能依赖所有输入方式都会先产生 blur。
异步验证另有业务请求相关性；框架只保证目标和所有者资格，不宣称绑定自动等待服务器接受。

**验收反例：**格式化打断 nihao；拒绝后因 Signal 没变化而残留输入；重置被迟到候选覆盖；
全局 invalid 拒绝本应合法的可选空值。

## 5. 逻辑所属与展示位置契约

| 关系 | 决定什么 | 不决定什么 |
| --- | --- | --- |
| 执行/生命周期所有者 | callback context、任务、清理归属 | 坐标和绘制顺序 |
| 布局位置与 anchor | 几何、滚动、裁剪、定位 | 回调改归另一个业务组件 |
| 交互边界所属 | 模态允许哪些子弹层、关闭和焦点修复 | 改写业务 open 或复制编辑状态 |

迁移展示位置保持既有执行所有者，不因 overlay 改归全局根。
这不等于普通 Rust 闭包自动捕获动态 context；注册时点仍决定所有者，构造/延迟构造入口须明确。
首版不承诺任意已挂载子树跨窗口迁移仍保持身份。
anchor 使用有效目标关系，不靠同名查找维持。标签关系优先局部装配，不要求手写字符串拼接。
简单内容用参数/builder，实际需要动态或脱离子树的部件时才增加注册。

### 先确定两类政策

| 政策 | 模态 Dialog | 编辑器建议 |
| --- | --- | --- |
| 打开焦点 | 进入有效初始目标；无目标时有明确容器策略 | 留在编辑器，active 项不是键盘焦点 |
| 背景输入 | 模态边界阻断，合法子弹层仍可操作 | 不建立模态屏障 |
| Escape | IME 优先，再请求关闭最内层可关闭范围 | IME 优先，再关闭建议，不误关外层 |
| 关闭恢复 | 本层仍持有焦点时，尝试返回存活且可聚焦的实际打开者 | 通常无需恢复，编辑器始终持有焦点 |
| 关联失效 | owner 释放或已有 anchor 失效，退役该次关联 | 编辑器/anchor 失效立即退役，迟到选择无效 |

Escape 请求已经处理但被业务拒绝，不再继续关闭外层。外部点击按最内层范围处理，
不自动把关闭模态层的同一次点击重放给背景。焦点已被应用合法转移，关闭不抢回；
恢复失败交给窗口正常修复，不寻找新同名按钮顶替。

open 是业务展示意图，挂载是当前兑现结果，不是重复状态。
anchor 消失先撤销悬空交互资格，向仍存活所有者报告无法展示/关闭请求，不擅自改应用 Signal。
新同名 anchor 不复活旧关联，需要新的有效关联/打开过程。
无法兑现的 open 在稳定边界可解释，不能静默保留不可见焦点陷阱。

**验收反例：**overlay 读取错误 context；建议抢走 IME 焦点；Escape 连关两层；
关闭将焦点恢复到已替换的同名目标。

## 6. 从契约推导最小公开面

| 类别 | 候选公开能力 | 私有或留在 kit |
| --- | --- | --- |
| 状态与执行 | 现有状态、派生、作用域组合、context 和任务工具 | 准入、调度、释放进度、代次 |
| 内容与结构 | 不透明 View、有限内容构造、条件/keyed 组合 | 挂载表示、内部文本对象、结构修复 |
| 展示与几何 | 类型化样式、共享文本属性、必要的滚动/几何操作 | 缓存、失效、测量阶段能力和输出提交 |
| 语义与输入 | 声明语义、类型化事件、可复用动作能力、文本绑定 | 标准控件装配、路由与 IME 仲裁 |
| 复杂组合 | 通用展示层、锚定和必要交互范围能力；最小受约束接口 | kit builder 表达字段、选项、Dialog 与建议的具体政策 |

这四份契约无需四个新运行层。优先删除挂载表示泄露、无条件 child 能力、
内部链接与应用 children 混用、复合组件的模糊配置目标。
Model 与 Behavior 不因名称已有就获得保留权：下一步比较直接 Signal/闭包适配的成本，
以及现有 Behavior 是否足以承担所需能力，而不扩大事件系统。

## 7. 纸面组合检查

| 场景 | 原语与基础能力组合 | API 推演要回答的问题 |
| --- | --- | --- |
| 图标 + 动态文字 Button | 容器内容、单动作根、共享名称/状态、类型化外观 | 如何限制交互标签；自定义控件怎样获得完整动作能力 |
| 前后缀 + 错误说明 Field | 外部布局、稳定编辑内容、实际控件关系、局部草稿政策 | builder 配置目标；Signal 与闭包适配签名 |
| Dialog 内输入建议 | 稳定编辑器、keyed 选项、active/selected 分离、逻辑关联 | anchor 和局部装配怎样简洁表达，不暴露内部 NodeId 操作 |

纸面检查没有证明需要通用 Parts 系统或 VM，也没有证明 API 易用或平台正确。
下一步只推演候选 Rust API：比较普通参数/builder 与必要局部组合接口，列出替代的当前入口；
对编辑仲裁、禁用焦点和关闭请求拒绝做时序检查，再冻结契约、进入实现切片。
