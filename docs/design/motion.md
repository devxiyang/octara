# Octara 动画架构

动画是窗口对已结算状态的呈现。Signals 更新目标值和组件结构，保留树记录当前挂载，布局计算目标几何。窗口按应用时钟采样同一组呈现值，交给绘制、命中、焦点范围和平台适配器。浮层退出、列表重排、输入焦点和手势收尾用同一套时间与身份规则。[总体架构](../ARCHITECTURE.md) · [窗口更新](core.md)

## 一条时间线

应用使用单调时钟。窗口宿主送入事件和帧时刻，任务、长按、滚动和动效从同一时间基准读取时间。无窗口测试通过 `App::advance_to` 推进。给定同一串带时间的目标更新，在同一时刻采样应得到相同呈现值和完成状态。显示刷新率和宿主调度影响采样间隔。曲线在启动时确定结束时刻，跨过该时刻后即可结清。这个规则同时适用于频繁采样和跳过中间帧。[应用时钟](../../crates/octara/src/app/time.rs) · [Track 的起点与终点](../../crates/octara-primitives/src/motion.rs#L246) · [W3C 时序模型](https://www.w3.org/TR/web-animations-1/#stateless) · [Functional Reactive Animation](https://conal.net/papers/icfp97/)

每次目标改变，轨道先在该次更新时间采样原轨道，再从采样值启动新段。弹簧继承速度，定时淡变按自己的曲线推进。同一更新时间内被绑定合并的中间目标以最终结算值为准。帧采样只更新呈现和到期资源，业务 Signal 由输入、任务及应用命令推进。[当前属性更新](../../crates/octara/src/kernel/anim.rs#L194)

一次窗口更新沿用现有的准备和提交协议。Signals 结算结构和样式目标，布局提供目标矩形，窗口在该次更新的 App 时刻采样。下一次输入先推进到自己的时刻，再对同一呈现规则和当前交互树做命中与投递。只随时间变化的颜色、阴影和透明度可以直接出新画面，布局与业务绑定继续按自己的失效条件执行。[窗口帧提交](../../crates/octara/src/app/frame.rs) · [应用时钟](../../crates/octara/src/app/time.rs)

同次提交的多个轨道共用起点和帧时刻。显式延迟或关键帧可以在这个时刻上取样一段有限序列。等待结清使用有限动效的截止时刻。加载指示等持续播放依附于可见表面，观察接口报告当前帧和播放状态，等待帧提交仍能返回。

## 目标、几何与呈现

| 变化 | 目标由谁给出 | 窗口怎样采样 |
| --- | --- | --- |
| 常驻属性 | 视图样式、状态覆写和主题 | 用现有 `Motion` 和 `Track` 插值颜色、阴影和透明度。同一个挂载在改变目标时从当前呈现值接续。 |
| 布局重排 | 已结算的视图、视口和布局约束 | Taffy 产出目标矩形。布局动效从已呈现的矩形移向目标。对同一帧，绘制、命中、辅助功能与文本范围查询引用同一组采样几何。 |
| 挂载与退出 | `show`、`keyed`、集合及浮层挂载 | 进退效果由被挂载的表面声明。退出时结构分支立即退休，上一帧的表面可以在原位继续绘制。 |
| 直接操控 | 捕获输入的窗口会话或原生转场 | 按当前触点、滚动量或宿主进度呈现。抬手后需要续行时，以当前位置和速度建立收尾。取消与完成按原会话身份结算。 |

布局约束、可用区和尺寸反馈按目标布局结算。呈现位置随时间采样。滚动、锚定和文字光标等关系需要显式选择所用的几何。比如移动的触发器应带着打开的浮层移动，同一时刻该位置也用于命中。当前锚定测量走目标布局的 `rect`，绘制走 `shown_frame`。收敛时用目标区域确定翻转和可用尺寸，再验证采样阶段如何跟随锚点，避免每帧重复测量内容。[目标布局](../../crates/octara/src/kernel.rs#L2263) · [布局轨道](../../crates/octara/src/kernel/anim.rs#L231) · [绘制与命中](../../crates/octara/src/kernel/paint.rs) · [系统文字查询](input.md#编辑器的视觉范围)

直接操控继续走窗口的输入会话。例如 UIKit 送回侧滑进度和完成结果，窗口用捕获的页面身份决定这次结果是否送达。触摸收尾按原命中的身份复核，键盘导致重新布局后也由同一个目标接收已确认的操作。应用按已接受的导航状态推进页面。[侧滑与触摸契约](input.md) · [现有触摸验收](interaction-scenarios.md#非模态浮层的关闭与焦点)

## 挂载身份与退出资源

一次结构提交决定哪个分支处于交互树中。关闭时，原节点立即退出命中、焦点、关闭仲裁、辅助功能和 Inspector 目标查找，原作用域在同一轮清理处理器、绑定和任务。绘制可以继续持有这次退出的表面和资源。旧画面按最后的摆放退出，窗口关闭时一并回收。焦点归还与关闭动作在结构结算时发生。[当前退出与释放](../../crates/octara/src/kernel/anim.rs#L349) · [作用域收尾](runtime-contract.md)

旧画面的呈现顺序来自它原来的浮层区域。Dialog 内的锚定面板保持画在 Dialog 上方，也保留与同级遮挡层的顺序。该区域重开时，新画面盖在旧画面上；两个画面使用同一个绘制位置和不同的挂载身份。绘制顺序在退出期间延续，交互顺序即时更新。[浮层绘制](../../crates/octara/src/kernel/paint.rs) · [浮层回归](../../crates/octara/tests/integration/overlay.rs)

重开创建新的挂载身份。旧抬手、回执和完成事件只能作用于原身份。仍挂载的元素可以反转属性轨道。已经退休的分支若需要连续视觉效果，可以把上一呈现值作为新画面的起点。新分支重新取得自己的焦点、动作目标和业务资源。一次更新内合并为同一展开值的情况按实际结构提交判定。[身份契约](../ARCHITECTURE.md#名称与身份) · [退出期间重开回归](../../crates/octara/tests/integration/overlay.rs)

结构动效的配置跟随实际表面，保留和回收跟随挂载边界。锚定浮层的定位容器负责摆放，一个实际内容根可以提供退出曲线，旧容器负责绘制。这轮原型用既有透明度曲线验证了这种交接。后续应让普通条件分支、列表项和浮层在挂载时解析同一种进退规则，再由退出路径统一消费。通用浮层的默认打开效果可让首帧直接可用。

## 表达方式与平台职责

`octara-primitives` 提供曲线、轨道和采样计算。`octara` 的窗口持有目标与活动轨道、输入会话和退出资源，用 App 时钟取样。绘制器消费采样后的绘制指令和图层顺序。Kit 可以复用曲线和组件的默认动效，应用继续通过现有状态及函数组合决定何时改变目标。[包边界](../ARCHITECTURE.md#从底层到应用) · [曲线和轨道](../../crates/octara-primitives/src/motion.rs)

`motion`、`color_motion`、`opacity_motion` 和 `layout_motion` 继续描述常驻属性或几何怎样到达目标。结构进退在内部拥有独立的策略和资源生命周期。现有透明度设置可以作为默认淡出。若列表与浮层的实际用法出现独立的进场与离场配置需求，再一起评审一个表面级 `transition` 入口。Kit 组合产品习惯，应用持续持有显隐、选择和提交策略。[现有样式接口](../../crates/octara/src/view/style.rs#L676)

平台适配器负责提交绘制和原生表面，以及报告显示、取消或完成。Core 决定对应窗口、挂载和输入会话是否仍有效。系统的减少动效设置进入窗口的共同采样规则，空间运动可以直接到位，透明度等变化使用短过渡。原生系统转场保留自己的时间进度，向 Core 交回带身份的结果。包含原生视图的退出效果需由宿主交付可保留的画面，或在语义退休时直接移除原生表面。[宿主边界](../ARCHITECTURE.md#平台宿主与-winit-的边界) · [现有减少动效规则](../../crates/octara-primitives/src/motion.rs#L100)

## Agent 怎样验收

Agent 需要知道窗口何时结算、当前正在呈现哪一帧、哪些轨道尚未完成，以及截图实际来自哪里。Inspector 从当前树读取目标、焦点和范围，从待结算状态读取动效。需要观察退出画面时，可从帧和待结算记录读出原位置与截止时间，交互令牌仍只来自可操作的现行树。截图记录来源和帧回执，旧退出的资源释放可以对照窗口日志或无窗口节点计数。[待结算工作](../../crates/octara/src/app/time.rs) · [Agent 反馈](agent-knowledge.md) · [截图契约](capture.md)

## Rune 与 Exact 的取舍

Rune 用独立轨道按绝对时间采样，常规弹簧重定向合并为一段并继承速度。`Scene` 用存在进度驱动进退效果。同一渲染节点中途重新出现时，会保留当前画面并更新退出代次。其 Kit 锚定面板采用立即出现、关闭淡出的规则。Octara 沿用绝对时间采样和呈现值接续，结构重开时用新挂载身份校验操作。[Rune 轨道与存在性](https://github.com/anomalyco/rune/blob/3686e94ae09545fd5f2a61e22aabfbeba1cd896f/crates/rune-motion/README.md#design) · [Rune 浮层动画](https://github.com/anomalyco/rune/blob/3686e94ae09545fd5f2a61e22aabfbeba1cd896f/crates/rune-kit/src/popover.rs#L11-L34)

Exact 的样式给出目标，CSS 或 Rust 采样相同的声明。退出节点先从宿主的可查找对象中退休，宿主持有旧表面直到收到释放。其虚拟行的布局容器可以使用单个实际内容根声明的退出效果。Exact 在本地调研版本还记录过振荡弹簧的完成时刻依赖采样帧率的问题。Octara 的完成测试应同时验证值和资源何时释放。[Exact Motion](https://github.com/expo/exact/blob/08c889a9de21a30b7c3b308422fc588cf1a480d3/motion/src/lib.rs#L1-L35) · [Exact 退出生命周期](https://github.com/expo/exact/blob/08c889a9de21a30b7c3b308422fc588cf1a480d3/host/apple/Sources/ExactKit/IOS/PresenceIOS.swift#L1-L62) · [退出规则](https://github.com/expo/exact/blob/08c889a9de21a30b7c3b308422fc588cf1a480d3/kernel/src/txn.rs#L1126-L1140) · [帧率问题记录](https://github.com/expo/exact/blob/08c889a9de21a30b7c3b308422fc588cf1a480d3/issues/20261110-spring-done-depends-on-frame-cadence.md)

## 推进步骤

1. **统一结构进退与完成的所有权。** 用普通分支、真实数据删除的虚拟行和锚定浮层对齐退出规则。滚动造成的视口挂载与回收沿用静默路径。验收直接跳到结束时刻和逐帧推进的结果一致，旧目标立即退休，动画结束只释放原资源。锚定浮层已经验证呈现顺序与交互身份可以独立推进。[退出动画原型实测](interaction-scenarios.md#浮层退出动画)
2. **统一呈现几何的读取。** 用重排列表上打开的浮层验证真实命中、焦点路径、文字范围与截图，分别核对目标布局与当前呈现。覆盖窗口缩放、键盘可用区和减少动效。
3. **核对直接操控与平台收尾。** 用嵌套滚动和侧滑返回复核中断、反向、取消以及结束后的焦点。无窗口驱动时钟验证时序，实窗和模拟器核对系统参与的部分。将反复出现的观察成本整理到现有 Inspector 回执上。
